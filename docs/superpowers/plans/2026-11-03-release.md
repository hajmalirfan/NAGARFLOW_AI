# PostgreSQL and Deployment Package Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prove the backend on PostgreSQL, and prepare a tested deployment package without going live.

**Architecture:** The test fixtures switch to PostgreSQL when `TEST_DATABASE_URL` is set, against a throwaway `initdb` cluster. Production safety lives in `check_production_settings`. The package is two Dockerfiles, an nginx config and `docker-compose.prod.yml`, checked by a read-only smoke script.

**Tech Stack:** FastAPI, SQLAlchemy, psycopg 3, PostgreSQL 18 (tests) and 16 (containers), Docker, nginx, pytest, Vitest.

**Spec:** `docs/superpowers/specs/2026-11-03-release-design.md`

## Global Constraints

- Branch `feat/release`. Backend: `.venv/Scripts/python -m pytest -q` from `backend`. Frontend: `npx vitest run` from `frontend`.
- Never touch the installed `postgresql-x64-18` service or its data. Use a cluster made with `initdb` in the scratchpad, on port 55432.
- A PostgreSQL test URL must name a database whose name ends in `_test`, or the suite stops before connecting.
- The example password `change-this-local-password` and the example JWT secret are refused in production.
- The roads file is never copied into an image or into git. It is mounted read-only from `ROAD_NETWORK_HOST_PATH`.
- No `.env`, real secret or dataset file is committed. Throwaway credentials are generated at run time and stay in the scratchpad.
- Step 25 is recorded as "prepared, not deployed".

## Decisions the spec left open

- **Roads path check:** the spec both refuses a road path that "does not point at a file" and only warns when the file is missing. Production refuses an empty `ROAD_NETWORK_PATH` and warns when it is not an existing file.
- **Resetting PostgreSQL between tests:** each test truncates every table with `RESTART IDENTITY CASCADE`, rather than rebuilding the schema. This is faster, and ids start at 1 as they do on SQLite.
- **Throwaway SQLite engines:** tests that build their own engines for upgrade checks stay on SQLite. The new PostgreSQL tests cover the upgrades there.

## Review Focus

Each line has a test in the owning task.

1. Two saves race on the same unique code. The depot, storage point and facility routes do not catch `IntegrityError` today, so the loser would get a 500 instead of 409 (Task 2).
2. `TEST_DATABASE_URL` points at a real database. The suite must refuse before it truncates anything (Task 1).
3. `X-Forwarded-For` is missing, shorter than the hop count, or forged with extra entries on the left. The address used is never one the client chose (Task 4).
4. A production start with every setting valid except one. Each check refuses on its own, and a fully valid set starts (Task 3).
5. The smoke check meets a server that is down or returns HTML. It reports a failure, and does not crash (Task 6).
